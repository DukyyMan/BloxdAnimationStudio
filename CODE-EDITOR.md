# Code Editor (initial integration)

Open **</>** in the dock. The editor interprets a limited subset of the previous BloxdAnimationMaker scripting language locally, then validates the result against this Studio's scene command engine. Validate is a dry run; Generate applies one undoable scene change. Script-created characters, blocks, items and keys are ordinary editor data. The script source itself is not saved in project files: copy it elsewhere to keep it.

The supported methods and example are displayed in the editor. This is **not yet the complete previous API**: custom mesh builders, mobs, lighting animation, easing options, FPS control, asset search, attachments, replace-generated, and update of existing transforms are not implemented. Animation and thumbnail are labels for the same scene; thumbnail scripts can omit timeline methods, but this does not introduce a separate rendering mode. Use the existing PNG export. Existing camera keys at a requested time are preserved, so `camera.set` will not override a pre-existing key at 0; edit/remove that key manually first. Existing generated objects with the same ID retain their manual transforms and keys. New keys at occupied times are skipped rather than replacing manual work; omitted objects are never deleted. Terrain writes and lighting changes explicitly requested by a script affect the shared scene. As with the original command system, applying a script commits pending scene edits. Undo reverses the whole application.

Objects use explicit IDs stored in their project options, including after save/load. Duplicate generated IDs are rejected. IDs must meet the command engine's constraints. Scripts use `async function main(api)` with the previous interpreter's bounded JavaScript subset, not browser JavaScript: no DOM, network, imports, eval, or arbitrary browser APIs. Script execution and scene commands are bounded. Validation and generation use the same compiled result, and generation refuses a stale scene snapshot.

Run `npm run test:code` for the adapter tests, `npm run build:interpreter` after changing the interpreter source, and `npm run build` for the standalone editor. The interpreter derives from DukyyMan/BloxdAnimationMaker (MIT); its license and Acorn's license are in `tools/script/` and included in standalone builds.
